# Проект: автопостинг в Max Messenger

> ## ⚠️ ТЕКУЩИЙ РЕЖИМ: 2-й круг (ротация тем из Notion)
>
> Новые темы исчерпаны. Сейчас мы **не ищем новости** (Шаг 1 не используется), а публикуем
> уже имеющиеся темы из Notion **по второму кругу**: 7 постов в день, разные тематики,
> БЕЗ недавних постов (аудитория их помнит). Темы заранее расписываются по датам.
> Этот раздел **переопределяет** Шаги 1, 2, 5 и 8 обычного алгоритма. Шаги 3, 4, 6, 7, 9
> (шаблоны, написание текста, промпт картинки, запись в `post-content.json`, вывод) —
> как раньше.
>
> **База:** data source `collection://7904954e-7d46-4416-b53d-2a25b87a4179`.
> Реальный порядок публикаций задаёт системная колонка `createdTime` (поле «Дата»
> бесполезно — у всех одинаковое). Темы различаем по заголовку/описанию (поля рубрики нет).
>
> **Поля учёта (добавлены в базу):**
> - `Запланировано на` (date) — на какой день назначена тема;
> - `Круг` (number) — номер круга: 1 = исходные публикации, 2 = текущий, далее 3, 4…;
> - `Опубликовано` (checkbox) — ставится `true` после успешной отправки в Max (когда именно —
>   см. «Отметки в Notion» ниже).
>
> **Правила ротации:**
> - Защитное окно — **2 месяца**: тему можно брать, только если её «последний показ»
>   (`COALESCE("Запланировано на", createdTime)`) был >2 мес назад.
> - За один круг тема публикуется **ровно один раз** (гарантирует условие `Круг < R`).
> - При повторе контент **переписывается заново**: другой шаблон (№1/№2/№3), свежий текст,
>   новая картинка. Микс шаблонов дня №1×3/№2×2/№3×2 и подача «когда к врачу» сохраняются.
>
> **Текущий заполняемый круг R** (выводится из базы, без внешнего состояния):
> `maxRound = MAX(COALESCE("Круг",1))`; R = maxRound, если есть темы с `COALESCE("Круг",1) < maxRound`,
> иначе R = maxRound + 1. (На старте все «Круг» пусты → R = 2.)
>
> **Пул тем, доступных для планирования в круг R:**
> ```sql
> SELECT url, createdTime, "Круг", "date:Запланировано на:start" AS plan,
>        "Заголовок", "Краткое но точное описание сути статьи" AS descr
> FROM "collection://7904954e-7d46-4416-b53d-2a25b87a4179"
> WHERE "Заголовок" IS NOT NULL
>   AND COALESCE("Круг",1) < :R
>   AND COALESCE("date:Запланировано на:start", createdTime) < date('now','-2 months')
> ORDER BY COALESCE("date:Запланировано на:start", createdTime) ASC;
> ```
>
> ### Процедура A — Планирование месяца (держим ~30 дней расписанными вперёд)
> 1. Определить R и вытащить пул (SQL выше).
> 2. Сгруппировать кандидатов по тематикам (по заголовку/описанию).
> 3. Разложить на ~30 дат по 7 тем: в каждом дне **7 РАЗНЫХ тематик**; темы распределены
>    по всему окну (НЕ «самые старые подряд»); соседние дни не кластеризуются по одной теме;
>    среди кандидатов — лёгкая рандомизация + приоритет более старым.
> 4. Каждой выбранной строке проставить `Круг = R` и `Запланировано на = <дата>`
>    (`notion-update-page`, command `update_properties`).
> 5. Если пул опустел посреди планирования → поднять R (новый круг) и продолжить
>    (это и есть авто-перетасовка на следующий круг).
>
> ### Процедура B — Публикация на дату
> Триггеры: **«сделай посты на ДД.ММ.ГГГГ»** → эта дата; **«ещё 7»** → ближайшая
> расписанная неопубликованная дата (если нет — сначала Процедура A).
> 1. Достать 7 строк:
>    `WHERE "date:Запланировано на:start" = :D AND COALESCE("Опубликовано",0)=0`.
>    Если на дату пусто — сначала выполнить Процедуру A для этой даты.
> 2. **Сообщение-заголовок дня.** Перед семёркой постов отправить в тот же канал отдельное
>    текстовое сообщение **«Посты на ДД.ММ.ГГГГ»** (без картинки):
>    ```bash
>    cd /home/user/AutoMaxDnevnikFarmacevta2 && rm -f browser-profile/SingletonLock browser-profile/SingletonCookie browser-profile/SingletonSocket 2>/dev/null; HEADER_TEXT="Посты на ДД.ММ.ГГГГ" xvfb-run --auto-servernum npx playwright test tests/send-header.spec.ts 2>&1 | grep -E "passed|failed|Error" | tail -10
>    ```
>    Дождаться «1 passed».
> 3. Назначить шаблоны дня: №1×3 / №2×2 / №3×2.
> 4. Для каждой из 7 тем ПО ОЧЕРЕДИ: переписать заново (Шаги 3,4,6,7) → `post-content.json`
>    → `send-post.spec.ts` (ждать «1 passed»). В Notion между постами НЕ писать — только
>    запомнить id страниц успешно отправленных постов.
> 5. По мере расходования месяца — дозапланировать следующий месяц (Процедура A).
> 6. Проставить отметки `Опубликовано` (см. «Отметки в Notion») и вывести итоговую таблицу:
>    тема / шаблон / статус.
>
> ### Отметки в Notion — только в конце всего запроса
> - `Опубликовано = __YES__` ставится **только после того, как закончены ВСЕ публикации в Max
>   по запросу пользователя**, а не после каждого поста и не после каждого дня.
> - Ставится **по одному вызову `notion-update-page` на страницу** (`update_properties`),
>   только для постов, которые реально ушли («1 passed» / строка `POST <id>` в `done.txt`).
> - Запрос на один день → 7 отметок после 7-го поста; запрос на неделю → 49 отметок после
>   последней публикации 7-го дня.
> - Если публикация прервалась — отметить только реально отправленные посты.
>
> ### Режим генерации картинок: «по одному» (по умолчанию) или «параллельно»
> - **По умолчанию — «по одному»:** шаги 1–6 выше как есть, картинка генерируется внутри
>   `send-post.spec.ts` для каждого поста отдельно.
> - **«Параллельно» — ТОЛЬКО если пользователь прямо написал «генерируй параллельно»**
>   (или аналогично). Если сказано «по одному» или про режим ничего не сказано — параллельный
>   режим НЕ использовать. Как работает:
>   1. Написать тексты и промпты всех постов дня в очередь `post-queue/<YYYY-MM-DD>.json`
>      (gitignore):
>      ```json
>      { "date": "19.10.2026", "header": true, "posts": [
>        { "id": "<id страницы Notion без дефисов>", "template": 1, "title": "<Заголовок>",
>          "postText": "...", "imagePrompt": "...", "imagePromptSimple": "<упрощённый промпт>" } ] }
>      ```
>      `header: false` — если заголовок дня уже отправлен.
>   2. Запустить в фоне `bash scripts/run-day.sh post-queue/<YYYY-MM-DD>.json`: параллельно
>      генерирует все картинки дня (`scripts/pregen-images.js` → `post-queue/img/<id>.png`),
>      отправляет заголовок «Посты на ДД.ММ.ГГГГ ⬇️», затем посты СТРОГО по очереди; при первой
>      ошибке — стоп. Повторный запуск не дублирует уже отправленное (`post-queue/done.txt`).
>      Картинки на следующие дни можно заранее сгенерировать отдельно:
>      `node scripts/pregen-images.js post-queue/<дата>.json`. Не запускать больше ~7 генераций
>      одновременно: kie.ai отвечает 429 (скрипт ждёт и повторяет, но очередь замедляется).
>   3. Когда опубликованы ВСЕ дни запроса — по строкам `POST <id> ...` из `post-queue/done.txt`
>      проставить в Notion `Опубликовано = __YES__` по одному на страницу (скрипт Notion не трогает).
>
> **Антидубль в этом режиме:** полный семантический поиск по базе НЕ нужен (тема в базе
> намеренно); неповтор за круг гарантирует `Круг < R`. Контролируем лишь, что в одном дне
> нет двух одинаковых тематик.

## Команда «Сгенерировать пост»

Когда пользователь просит сгенерировать пост о здоровье, строго следуй алгоритму ниже.

---

## Шаг 1 — Поиск новости

Выполни WebSearch по следующим запросам:
- `едицина на дому здоровье на дому упражнения домашние средства лечения рецепты домашних медицинских средств новости 2026`
- `здоровье на дому советы 2026 апрель`

Критерии отбора:
- Тема: домашние средства лечения, упражнения для здоровья дома, здоровое питание, народная медицина
- Практична и применима в жизни (не законодательство/бюрократия)
- Понятна широкой аудитории без медобразования

---

## Шаг 2 — Проверка в Notion (не брали ли эту статью раньше)

> ⚠️ **ОБЯЗАТЕЛЬНО: сверяй тему КАЖДОГО поста со ВСЕЙ базой Notion перед публикацией.**
> Перед тем как взять тему, выполни семантический поиск по базе через Notion MCP
> (`notion-search` с `data_source_url: collection://7904954e-7d46-4416-b53d-2a25b87a4179`),
> используя несколько формулировок темы. Внимательно сравни найденные заголовки и описания
> по СМЫСЛУ (а не только по URL) со всей базой. Если есть хоть один семантически похожий
> пост — тема считается дублем, **бери другую** и повтори проверку.
>
> Не полагайся только на `notion-check.spec.ts`: он ходит в Notion REST API через
> `process.env.NOTION_TOKEN`, и если токена нет — запрос молча возвращает «дублей нет».
> Поэтому основной и обязательный способ проверки — Notion MCP. Семантический поиск
> отдаёт результаты пачками, поэтому делай несколько запросов с разными формулировками.

Запиши файл `article-check.json` в корне проекта:

```json
{ "url": "<URL найденной статьи>", "description": "<1-2 предложения о сути статьи>" }
```

Затем (если токен Notion доступен) можешь дополнительно запустить через Bash:

```bash
npx playwright test tests/notion-check.spec.ts
```

Прочитай `article-check-result.json` и проверь два условия:
1. Если `urlMatch: true` — этот URL уже использовался, найди другую статью и повтори проверку.
2. Если `urlMatch: false` — прочитай список `recentDescriptions` и сравни семантически с описанием текущей статьи. Если по смыслу похожая есть — найди другую статью и повтори проверку.

---

## Шаг 3 — Выбор шаблона поста

**Выбери шаблон случайным образом** — сгенерируй случайное число от 1 до 3 и используй соответствующий шаблон:
- **1** → Шаблон №1 (короткий текст + простая инфографика)
- **2** → Шаблон №2 (2 предложения + подробная инфографика)
- **3** → Шаблон №3 (полный пост + реалистичная фотография)

Запомни выбранный номер шаблона — он влияет на шаги 4 и 6.

---

## Шаг 4 — Написание поста для Max Messenger

### Шаблон №1 — Короткий текст

Напиши пост ровно из **4 предложений** на основе найденной статьи. Никаких разделов, абзацев и вопросов в конце — только короткий, ёмкий текст с эмодзи в начале.

Пример формата:
```
**[ЭМОДЗИ] [Предложение 1 — суть и польза]**

[Предложение 2 — суть и польза (продолжение)]

[Предложение 3 — конкретный совет или лайфхак]
[Предложение 4]
```

Правила стиля:
- **Предложение 1 — жирным шрифтом** (`**текст**`)
- Последние 3 предложения — обычным шрифтом (без звёздочек)
- Тон: разговорный, дружелюбный, без канцелярита
- Максимально человеческий стиль, без признаков ИИ-генерации
- Суммарно не более 4 предложений

---

### Шаблон №2 — Короткий текст + подробная инфографика

Напиши пост ровно из **2 предложений** на основе найденной статьи. Без разделов, абзацев и вопросов в конце — только самая суть с эмодзи в начале.

Пример формата:
```
[ЭМОДЗИ] [Предложение 1 — суть и польза]

[Предложение 2 — конкретный совет или лайфхак]
```

Правила стиля:
- Тон: разговорный, дружелюбный, без канцелярита
- Максимально человеческий стиль, без признаков ИИ-генерации
- Строго 2 предложения, не больше и не меньше

---

### Шаблон №3 — Полный пост

Используй шаблон:

```
[ЭМОДЗИ] [ЦЕПЛЯЮЩИЙ ЗАГОЛОВОК — до 10 слов]

[Абзац 1 — суть новости, 2–3 коротких предложения]

[Абзац 2 — практическая польза / что делать, 2–3 предложения]

[Абзац 3 — конкретный совет или лайфхак, 2–3 предложения]

[ВОВЛЕКАЮЩИЙ ВОПРОС к аудитории?]
👍 — [ответ «да»]
❤️ — [ответ «нет» или альтернатива]
```

Правила стиля:
- Заголовок: с эмодзи, интригующий, до 10 слов
- Абзацы: 2–3 предложения, короткие и чёткие
- Тон: разговорный, дружелюбный, без канцелярита
- Максимально человеческий стиль, без признаков ИИ-генерации
- Вопрос в конце: простой, бинарный, с 👍 и ❤️

## Шаг 6 — Генерация промпта для картинки (kie.ai)

Промпт пишется на **английском языке**. Тип промпта зависит от выбранного шаблона:

### Шаблон №1 — Простая инфографика

Напиши промпт для генерации **простой инфографики**:
- Стиль: чистая плоская инфографика, минималистичный дизайн, 2–4 иконки или блока с ключевыми фактами из статьи
- Светлый фон, читаемые подписи, без лишних деталей
- **Все подписи, заголовки и текст на изображении — на русском языке**
- Соотношение сторон 4:3 (задаётся отдельно в API, в промпт не включать)
- Длина промпта: средняя, достаточная для генерации, без излишеств

### Шаблон №2 — Подробная инфографика

Напиши промпт для генерации **подробной инфографики**:
- Стиль: детальная инфографика с заголовком, разделами, иконками, цифрами и краткими подписями
- Охватывает основные факты, советы или шаги из статьи
- Профессиональный дизайн, гармоничная цветовая схема
- **Все подписи, заголовки и текст на изображении — на русском языке**
- Соотношение сторон 4:3 (задаётся отдельно в API, в промпт не включать)
- Длина промпта: средняя, достаточная для генерации, без излишеств

### Шаблон №3 — Реалистичная фотография

Напиши промпт на **английском языке** для генерации реалистичной фотографии к посту:
- Стиль: реалистичная фотография, как с фотоаппарата
- Если на фото есть человек — расположить так, чтобы лицо не было видно
- Избегать текста на изображении
- Соотношение сторон 4:3 (задаётся отдельно в API, в промпт не включать)
- Длина промпта: средняя, достаточная для генерации, без излишеств

## Шаг 8 — Автоматическая публикация в Max Messenger

Сразу после сохранения `post-content.json` — без каких-либо пауз и вопросов — запусти тест через Bash:

```bash
xvfb-run --auto-servernum npx playwright test tests/send-post.spec.ts
```

Тест автоматически:
1. Читает `post-content.json`
2. Генерирует картинку через kie.ai (~1–3 мин)
3. Отправляет пост с картинкой в канал Max Messenger

Дожидайся завершения теста и сообщи пользователю результат.

---

## Шаг 9 — Вывод результата

Выведи пользователю:
1. Использованный шаблон (№1 / №2 / №3)
2. Текст поста (или пометку «без текста» для шаблона №2)
3. Промпт для картинки
4. Статус публикации (успешно / ошибка)
